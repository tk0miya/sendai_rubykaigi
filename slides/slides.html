なぜ取りこぼすのか

rubocop-erb は ERB タグごとに Lint をかけている

<% count = items.size %>
<% if foo == nil %>
  <p>yes</p>
<% else %>
<% end %>
  • タグ単位の分析では文脈が失われる

Lint の際に文脈が失われている

  • 制御構造
    • if のみ、else のみのタグは検査できない
    • 制御構造全体を俯瞰した cop は失敗する
    • rubocop-erb は if や do を削って検査を強行する
  • 変数スコープ
    • タグごとに Lint をかけるので参照箇所がわからない
  • → 誤検知が多いため、多くの cop を無効化している

なぜ cop を無効化するのか

  • Ruby コードへの変換により誤検知を生んでいる
  • rubocop-erb は誤検知を避けるため cop を無効化している
  • 発生しうる問題
    • 1. コード変換による問題
    • 2. HTML 消去による問題
    • 3. ERB 風の Ruby の書き方の問題
    • 4. レイアウトに対する指摘

1. コード変換による問題 (1)

変換前 
<%= link_to "Home", root_path %>
変換後 
    link_to "Home", root_path  ;
  • 変換で生まれたスペースやセミコロンに対する指摘
    • Layout/ExtraSpacing: ; の前の 2 つの空白
    • Style/Semicolon: 文の終わりの ;

1. コード変換による問題 (2)

変換前 
<h1><%= @title %></h1>
<p><%= @description %></p>
変換後 
        @title  ;
       @description  ;
  • <%= で出力している式に Lint/Void（値を使わない式）
    • 変換で <%= が消え、値を捨てる文に見える

2. HTML 消去による問題

変換前 
<% if morning? %>
  Good morning, <%= user.name %>
<% else %>
  Hello, <%= user.name %>
<% end %>
変換後 
   if morning?  ;
                    user.name  ;
   else  ;
             user.name  ;
   end  ;
  • Ruby に変換すると HTML が消え、HTML だけが違う分岐が同じに見える
  • → Lint/DuplicateBranch（誤検知）

3. ERB 風の Ruby の書き方の問題

<%= link_to(user_path(user)) do %>Profile<% end %>
  • ERB では { … } より do/end の方が自然に見える
  • Ruby 向けの cop では ERB に不向きなものがある
    • Style/BlockDelimiters: { … } にせよ
    • Style/SingleLineDoEndBlock: 複数行にせよ

4. レイアウトに対する指摘 (1)

変換前 
<% if admin %>
  <div class="admin">
    <%= render "admin" %>
  </div>
<% end %>
変換後 
   if admin  ;

        render "admin"  ;

   end  ;
  • HTML パートによって ERB タグの記述位置が変化する
  • インデントに対する指摘は誤検知
    • 例: Layout/IndentationWidth

4. レイアウトに対する指摘 (2)

変換前 
<%= form_with do |f| %>
  <%= f.text_field :name %>
<% end %>
変換後 
    form_with do |f|  ;
      f.text_field :name  ;
   end  ;
  • form_with と end の位置のズレを指摘される
    • Layout/BlockAlignment
  • ERB の開始タグの文字数によるもので誤検知

tk0miya/rubocop-herb

  • 文書全体方式を採用
  • 検知精度を上げるため 4 つのアプローチを採用
    • 1. 埋め込みブロックを代入に変換
    • 2. HTML を Ruby 式に変換
    • 3. 変換で生まれた文字への指摘を除外
    • 4. タグをまたいだ構造への指摘を除外

1. 埋め込みブロックを代入に変換

変換前 
<%= @title %>
<%= @description %>
変換後 
_ = @title;
_ = @description;
  • <%= は代入文（_ =）に変換する
    • 「値を出力に使う」という意味が残る
  • Lint/Void の誤検知が出ない

2. HTML を Ruby 式に変換

変換前 
<% if morning? %>
  Good morning, <%= user.name %>
<% else %>
  Hello, <%= user.name %>
<% end %>
変換後 
   if morning?;
  _a;           _ = user.name;
   else;
  _a;    _ = user.name;
   end;
  • HTML のタグは div; に、テキストは _a; に変換する
    • さらに AST 上では HTML ごとに別の識別子を与え、区別可能とする

2. HTML を Ruby 式に変換

変換前 
<% if morning? %>
  Good morning, <%= user.name %>
<% else %>
  Hello, <%= user.name %>
<% end %>
変換後 
   if morning?;
  _a;           _ = user.name;
   else;
  _a;    _ = user.name;
   end;
  • これにより次の誤検知がなくなる
    • Lint/DuplicateBranch
    • Lint/EmptyConditionalBody、Style/EmptyElse

3. 変換で生まれた文字への指摘を除外

<p><% @title = 'Home';  @nav = :home %></p>
p;    @title = 'Home';  @nav = :home;  p;  
 ~~~~                ~~             ~~  ~~~
1 行目: ERB、2 行目: 変換後の Ruby、3 行目: RuboCop の指摘の位置
  • 変換後の Ruby に RuboCop をかけると 8 件の指摘
    • Style/Semicolon、Layout/ExtraSpacing、Layout/TrailingWhitespace

3. 変換で生まれた文字への指摘を除外

<p><% @title = 'Home';  @nav = :home %></p>
p;    @title = 'Home';  @nav = :home;  p;  
 ~~~~                ~~             ~~  ~~~
1 行目: ERB、2 行目: 変換後の Ruby、3 行目: RuboCop の指摘の位置
  • 変換コードに関わる cop は ERB タグ内のみ指摘を受け付ける
    • Style/Semicolon、Layout/ExtraSpacing など（23 個）
  • 報告するのはタグの中の 2 件だけ

4. タグをまたいだ構造への指摘を除外

タグをまたいだブロック → 指摘しない

<%= form_with do |f| %>
  <%= f.text_field :name %>
<% end %>

1 つのタグで閉じたブロック → 指摘する

<%= form_with do |f|
      f.text_field :name
    end %>

4. タグをまたいだ構造への指摘を除外

  • 制御構造が複数のERBタグをまたぐ場合の誤検知を減らす
    • レイアウトに対する指摘: Layout 系 7 個
      （Layout/BlockAlignment など）
    • ERB 風の書き方の問題: Style 系 4 個
      （Style/BlockDelimiters など）
  • 1 つのタグ内に書いた場合は指摘をする
